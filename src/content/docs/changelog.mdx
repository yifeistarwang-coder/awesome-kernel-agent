## v1.3：TIRx 章事实校订（2026-10-30）

本版不新增章节，只校订第 6 章的事实口径并补齐来源：术语 88 → 90 条，图示仍为 5 张，练习仍为 11 道。主要修订：

- **KCoral 的定位**：此前把「基准服务」与「kcoral 远程执行」写成两件工具。实际上 KCoral 本身持有 GPU、集中调度并返回测量结果与产物，基准服务与远程执行是同一件事的正反面；正文与图示已合并。
- **补齐负载契约的字段**：仓库里的契约是 `evolution/tasks/<name>.yaml`，含 `sota_baseline.name`、`spec`、`bench_timeout_s`、`banned_paths` 等字段，并在运行时渲染进 `PROMPT.md`；正文据此说明「baseline 由契约写死」「禁止事项可机械判定」。
- **补入编译期分析的实例**：博客记录同步分析抓出一个能通过 benchmark 的潜伏 mbarrier 生成 bug，正文用它支撑「编译期分析能抓到 benchmark 测不出来的问题」。
- **补全公开结果与口径**：MLC 博客的几何平均加速比共七项（区间 1.33×–6.84×），基线是各自优化过的参考实现，比较的是 GPU kernel 时间而非端到端延迟，硬件为 NVIDIA Blackwell（仓库契约写 B200 / sm_100）。
- **补充版本与许可**：harness 处于 0.1.x 早期版本，博客自陈基准结果可能在几天尺度上变化；TIRx 随 Apache TVM（Apache-2.0），tirx-kernels 标注 Apache-2.0，harness 仓库根目录无 LICENSE 文件、许可以官方为准。
- **新增与 Humanize 的关系**：MLC 公开的运行使用 Humanize 2 的 flame chase 流程，harness 文档把 Claude Code、Codex 与 Humanize 列为三种 agent 前端，说明工具层与编排层是可叠加的。

## 来源口径

本站不是任何项目的官方文档。写作时遵循以下口径：

1. 以公开的官方仓库、官方文档与论文为第一优先；中文解读只用于建立直觉，关键数字回到一手来源。
2. 数字尽量同时给出任务、硬件或预算条件、来源与时间；无法确认的细节标注“以官方为准”，不做推测性补全。
3. 区分事实与观点。论文报告的最好结果、社区经验与本站的教学建议，在文中分别表述。
4. 涉及快速演进的项目（尤其是 Humanize 2、KDA 新版本、ForgeKernel 与竞赛结果）时，写明核对日期，提醒读者可能已经变化。
5. 外部链接集中在[资料库](/resources/)，逐条标注核对日期（历史条目为 2026-10-29，v1.1 与 v1.4 新增条目为 2026-10-30，v1.5 新增条目为 2026-10-31）；链接失效或内容变更时，以官方页面为准。

## 已知限制

- Humanize 2 仍在演进，flow 名称、CLI 支持范围与预算接口可能变化；本站描述以 2026-10-29 的公开材料为基线。
- KDA 的团队隶属、版本号与竞赛成绩在不同材料中的表述不完全一致；本站采用谨慎措辞，具体以官方仓库与主页为准。
- KDA 官方博客中的 reward hacking 复盘与六道 acceptance gate 属一手材料，但本文只做转述；具体 gate 实现与参数以官方仓库为准。
- TIRx 的公开结果来自 MLC 自己的博客与 harness，与 KDA 官方博客的 baseline、硬件与测量口径不同，本站并列展示时明确标注不可直接比较。
- TIRx Harness 的部件清单依据其官方仓库 README 与 MLC 博客（核对于 2026-10-30）；负载契约的具体字段、workload 的注册方式与 harness 的版本成熟度以官方文档为准。harness 仓库根目录未见 LICENSE 文件，许可口径以官方为准。
- BBuf 仓库的 skill 条目、目录结构与 `scripts/query.py` 参数会变化；本章描述以 2026-10-30 的公开内容为基线。该仓库根目录未见 LICENSE 文件，许可口径以官方为准；PR 档案中的结论带审计日期，引用前需回到当前分支复核。
- ForgeKernel 处于 0.1.x 早期版本，其论文仍在 OpenReview 评审中（标为 ICLR 2027 under review）；本章描述以 2026-10-31 的仓库公开内容为基线，命令、模型、成绩与目录都可能变化。ForgeKernel 采用 Apache-2.0；其 leaderboard 评测器改写了 FlashInfer-Bench 与 SOL-ExecBench 的代码（两者同为 Apache-2.0）。
- ForgeKernel 的公开结果对照物分层：对专家库多数是几个百分点的领先，个别几十个百分点来自对其他 kernel 生成系统的比较；本章已逐行标注，但引用时仍需连同对照物与出处一起写。
- 部分应用结果（如 MLSys 赛道名次、HOA 满分）来自论文或中文解读，未逐项复现实验。
- 练习中的 CLI 命令只给结构，不给死参数；不同版本的非交互接口可能不同，使用前请读官方文档。
- 本站不提供 GPU 环境，性能数字不可直接与自己的硬件结果比较；练习以流程正确与证据完整为优先。
